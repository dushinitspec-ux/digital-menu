# Digital Menu — цифровое меню на ТВ

SaaS для кофеен, кафе, ресторанов, баров и кальянных. Владелец правит меню с телефона, а телевизоры в зале обновляются за доли секунды. Без интернета экран продолжает работать из кэша.

Исследование рынка, юридическая структура и план запуска лежат в [`reports/План запуска цифрового ТВ меню.md`](reports/План%20запуска%20цифрового%20ТВ%20меню.md).

## Что уже работает

| Часть | Возможности |
|---|---|
| **Панель владельца** (`/admin`) | Регистрация с готовым демо-меню под тип заведения. Меню: категории, позиции, размеры (S/M/L, 0,3/0,5), метки, фото, цены прямо в списке. Стоп-лист одним переключателем, отдельно для каждой точки сети. Сцены с живым превью, экраны и расписание по времени суток, медиатека, точки, команда с ролями, журнал действий. Интерфейс RU/EN, удобен с телефона. |
| **ТВ-плеер** (`/player`) | Сопряжение по 6-значному коду или QR. Обновления по SSE (в тестах 0,25–0,3 с от правки до экрана), запасной опрос раз в минуту с ETag. Офлайн-старт из кэша Service Worker: оболочка, шрифты, фото и видео. Смена сцен по расписанию по часам сервера. Пульс, удалённая перезагрузка, ночной перезапуск. Отдельная сборка для старых ТВ и приставок (Chromium 53+). |
| **Шаблоны** | Noir (тёмный, антиква и золото), Crema (светлый, для кофеен), Neon (гротеск и видео-фон). Раскладка по колонкам с выравниванием и листанием страниц. Видео- и фото-фоны, подсветка изменённой цены, пометки «нет в наличии». Режим табачного перечня по 15-ФЗ: одинаковый шрифт, чёрное на белом, по алфавиту, без картинок. |
| **API** | Fastify + PostgreSQL. Роли owner / admin / editor / viewer, изоляция организаций. Сессии в httpOnly-cookie, пароли на scrypt, защита от CSRF, лимиты на вход. Фото в WebP, видео в H.264 1080p через ffmpeg. Хранилище локальное или S3. Real-time через PostgreSQL LISTEN/NOTIFY, поэтому API масштабируется горизонтально. |
| **Два контура** | Один код и образ, а регион (`REGION=ru` или `eu`), домен, база и хранилище свои у каждого контура. Регистрация из «чужой» страны отправляется на другой домен, данные не смешиваются. |

Ещё не сделано (план v1 и v2 — в отчёте):
- оплата подписки (ЮKassa/Robokassa в RU, Paddle или Stripe в EU);
- нативная Android-обёртка плеера;
- интеграции с кассами (iiko, Quick Resto, Square);
- восстановление пароля по e-mail;
- тексты оферты и политики конфиденциальности (это работа юриста);
- пакеты для Tizen и webOS.

## Структура

```
apps/api        Fastify API, миграции SQL, раздаёт собранные панель и плеер
apps/admin      React-панель владельца (Vite)
apps/player     ТВ-плеер (Vite, legacy-сборка, Service Worker в public/sw.js)
packages/shared Контракт манифеста, расписание, деньги, zod-схемы, регионы
packages/renderer  Рендерер шаблонов: используется и плеером, и превью в панели
e2e/run.mjs     Сквозной тест в Chromium
deploy/         Caddyfile (HTTPS), скрипт бэкапа
```

Как это устроено:

```
Телефон владельца ──HTTPS──> API ──> PostgreSQL ──NOTIFY──> API (любой экземпляр)
                                │                                 │ SSE
                                └──> S3 (фото, видео) ── CDN ──> ТВ-плеер (кэш SW + localStorage)
```

Плеер получает **манифест**: сцены, категории, позиции с учётом стоп-листа точки, расписание и список медиа. Какую сцену показывать, он решает сам по часам. Поэтому смена «завтрак → ланч → вечер» работает и без сети.

## Запуск для разработки

Нужны Node.js 22+, pnpm 10 и PostgreSQL 16. Для перекодирования видео — ffmpeg (без него видео сохраняется как есть).

```bash
pnpm install
```

```bash
cp .env.example .env
```

```bash
createdb digital_menu
```

```bash
pnpm dev
```

API: http://localhost:3000, панель: http://localhost:5173/admin/, плеер: http://localhost:5174/player/. Миграции применяются при старте API.

Продакшен-сборка и запуск одним процессом (панель и плеер раздаёт API):

```bash
pnpm build && pnpm start
```

## Тесты

```bash
pnpm typecheck
```

```bash
pnpm test
```

Интеграционные тесты API требуют базу `digital_menu_test`: тесты очищают её схему. Адрес задаётся в `DATABASE_URL_TEST`.

```bash
pnpm build && pnpm e2e
```

Сквозной тест проходит путь владельца. Он регистрируется, телевизор показывает код, владелец добавляет экран, меняет цену (проверка: на экране быстрее 3 с) и ставит позицию на стоп. Затем ТВ уходит в офлайн и перезагружается из кэша. Нужен Playwright с Chromium.

## Деплой контура

Каждый контур — отдельный сервер в своей юрисдикции:
- **RU**: Yandex Cloud, Selectel или Timeweb, медиа в их S3, CDN российский.
- **EU**: Scaleway или OVH (Hetzner не обслуживает клиентов с российским адресом), медиа в S3 того же провайдера.

```bash
cp .env.ru.example .env
```

```bash
docker compose up -d --build
```

Caddy сам выпускает HTTPS-сертификат для `APP_DOMAIN`. Бакет медиа нужно открыть на публичное чтение и разрешить CORS `GET` с домена приложения: плеер кладёт файлы в офлайн-кэш через `fetch`. Бэкап базы делает `deploy/backup.sh` по cron, в хранилище того же контура.

| Переменная | Назначение |
|---|---|
| `REGION` | `ru` или `eu` — какой контур обслуживает этот экземпляр |
| `PUBLIC_URL`, `OTHER_REGION_URL` | свой адрес и адрес другого контура (для переадресации при регистрации) |
| `DATABASE_URL` | PostgreSQL этого контура |
| `STORAGE_DRIVER` | `local` (папка `STORAGE_DIR`) или `s3` |
| `S3_*`, `MEDIA_BASE_URL` | S3-совместимое хранилище и публичный адрес медиа (CDN) |
| `BRAND_NAME` | название бренда в интерфейсе (у контуров разные бренды) |
| `AUTH_RATE_LIMIT` | попыток входа и регистрации в минуту с IP (по умолчанию 10) |
| `MAX_UPLOAD_MB` | максимальный размер видео (по умолчанию 100) |

## Как подключить телевизор

1. **Рекомендуемый вариант — Android TV-приставка.** Поставьте браузер-киоск (например, Fully Kiosk Browser), откройте `https://<домен>/player/`, включите автозапуск при включении и запрет сна.
2. **Smart TV.** Откройте адрес плеера во встроенном браузере. В настройках ТВ **выключите автоотключение**: по правилам Ecodesign ЕС телевизоры уходят в режим ожидания через 4 часа без нажатий на пульт.
3. На экране появится код и QR. Отсканируйте QR телефоном или введите код в панели: **Экраны → Добавить экран**.

Красная точка в правом нижнем углу экрана значит, что больше 2 минут нет связи. Меню при этом продолжает показываться из кэша.

## Безопасность и данные

- Персональные данные — только аккаунты владельцев и сотрудников (имя, e-mail, хэш пароля). Гости заведения не регистрируются, меню не содержит ПДн.
- Устройство авторизуется своим токеном: плеер генерирует его сам, сервер хранит только SHA-256. У сессий хранится тоже только хэш.
- Изменения меню, сцен, экранов и команды пишутся в `audit_log`. Удалённый сотрудник теряет доступ сразу.
- RU-контур не обращается к иностранным сервисам: шрифты в сборке, без Google Fonts, Analytics, Cloudflare и Sentry SaaS.
